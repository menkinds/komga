# 2026-11-27 — 업데이트 후 Unavailable 해소 확인, 제목만 보이는 시리즈는 cBossard komga_sync의 제목 잠금 때문으로 확인(그대로 두기로 함)

- 목표/요청: 업데이트 뒤에도 Unavailable이 남는다는 확인 요청, 그리고 왜 어떤 시리즈는 `[작가] 제목 권수`로, 어떤 시리즈는 제목만 보이는지 원인 찾기.
- 도구: Claude Code (클라우드 세션, GBrain MCP 검색)
- 모델: claude-opus-5-5
- 토큰 사용량: 응답 수 105 · 입력 238 · 캐시 생성 358,619 · 캐시 읽기 18,399,756 · 출력 59,917 · 합계 18,818,530 (같은 대화 전체 누적값. 앞의 komga-2026-11-26-1 기록 숫자를 포함함)
- 핵심 프롬프트(원문):
  > 근데 업데이트 된 거 맞아? 스캔해도 남아있는데
  > 아직도 어떤 거는 작가랑 다 보이고 어떤 거는 제목만 보이는데 맞아?
  > 이미 메타데이터 꺼져있는데?
  > 엄청 많은 거 같아 혹시 cBossard의 fetch 관련인지 지브레인 훑어봐
  > 아냐 그냥 두자 상관없지?
- 진행 내용:
  1. GitHub Actions를 보니 수정 이미지 빌드가 아직 진행 중이었음. 이미지를 다시 받고 스캔하라고 안내. 배포 후 사용자 화면에서 Unavailable 항목이 사라진 것을 확인함.
  2. 제목 표시 차이의 첫 추정(파일 안 ComicInfo 정보)은 사용자 설정과 맞지 않아 틀림. 코드를 다시 읽어 "서버는 제목을 스스로 잠그지 않는다, 웹 편집이나 외부 API만 잠근다"를 확인.
  3. 사용자의 편집 화면 캡처에서 제목·정렬 제목·상태·권수 4칸만 잠긴 것을 확인.
  4. 사용자 요청으로 GBrain을 검색함. 같은 집의 다른 프로젝트 cBossard(만화 서재 웹앱)가 Komga에 이 4칸을 잠금과 함께 써 넣는 동기화 기능을 갖고 있음을 찾음. 잠긴 칸이 정확히 일치해 원인으로 판단.
  5. 영향 범위(화면 제목만, 재연결·검색·별점은 무관)를 설명했고, 사용자가 그대로 두기로 결정.
- 막힌 점 · 실패와 원인:
  - 설정 상태를 확인하지 않고 원인을 추정했다가 틀림.
  - 프로젝트 사이의 연결(cBossard → Komga 쓰기)은 코드 저장소 하나만 봐서는 보이지 않았음. GBrain에 남아 있던 다른 프로젝트 인계서로 찾음.
  - 또 영어로 답해 사용자가 지적함.
- 결과물: 문서 PR #9 머지(master `ac11656`). 코드 변경 없음. 원인 조사 결론과 "그대로 둔다"는 결정을 기록함.
