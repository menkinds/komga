# 2026-11-26 — 폴더 이름 변경+권 수 증가 시 옛 시리즈 Unavailable 잔류 수정(재연결 규칙 완화, 빈 휴지통 시리즈 삭제), PR #8 머지

- 목표/요청: 업데이트 뒤에도 옛 폴더 시리즈가 "Unavailable"로 계속 남는 문제 해결. 화면 표시는 폴더 이름(`[작가] 제목 권수`) 그대로 유지.
- 도구: Claude Code (클라우드 세션)
- 모델: claude-opus-5-5
- 토큰 사용량: 응답 수 67 · 입력 155 · 캐시 생성 126,621 · 캐시 읽기 10,020,009 · 출력 33,270 · 합계 10,180,055
- 핵심 프롬프트(원문):
  > komga 옛날에 만든 기능중에 폴더명에서 권수 바뀌면 어떻게 한다 있었지
  > 업데이트 한 뒤에 오래된 폴더가 unavailable이라고 계속 떠
  > (스크린샷: `今日の現場と終演ごはん` Unavailable, 옆에 `[えきあ] 今日の現場と終演ごはん 第01~02巻`)
  > 콤가에서 보여지는 표현 방식은 [작가] 제목 권수 유지하면서 AB 두안 다 하는 방법 있어?
  > 머지해.
- 진행 내용:
  1. 예전 포크 기능(폴더 이름이 바뀌어도 해시나 정리된 이름으로 같은 시리즈에 다시 잇기)과 스캔 흐름을 코드로 다시 읽어 설명.
  2. 원인 가설을 세우고 재현 테스트(3권 → 8권 이름 변경)를 먼저 만들어 실패를 확인. 옛 시리즈가 휴지통에 남음.
  3. 원인: 재연결 규칙이 "새 폴더 책의 과반도 맞아야" 해서 권 수가 두 배 이상 늘면 실패. 그러면 새 시리즈가 생기고 옛 책만 옮겨져 옛 시리즈가 빈 채로 남음. 기존 자동 삭제는 이 경로를 몰랐음.
  4. 두 가지 안을 표로 비교해 사용자에게 보여 주고, 사용자가 둘 다 선택. A: 옛 시리즈 책의 과반만 맞으면 재연결(시리즈 id·메타데이터·컬렉션 유지). B: 책이 모두 옮겨져 0권이 된 휴지통 시리즈는 스캔 끝에 삭제.
  5. 스크린샷 사례(1권 → 2권, 작가 표시·`第..巻` 붙음)와 두 시리즈 병합 사례를 테스트로 추가. 모두 통과 후 PR #8 머지.
- 막힌 점 · 실패와 원인:
  - Maven Central이 429(요청 과다)를 계속 돌려줘 빌드가 여러 번 멈춤. 2분 간격 재시도로 통과.
  - 전체 테스트 1014개 중 20개 실패. 모두 비ASCII 경로 `InvalidPathException`으로, 컨테이너 로케일 미설정 때문. UTF-8로 다시 돌려 통과.
  - B안 첫 테스트(한 시리즈를 두 폴더로 나누기)는 A안만으로 해결돼 B를 검증하지 못함. "두 시리즈를 한 폴더로 합치기"로 바꿔 B가 필요한 경우를 재현.
  - 처음 설명("두 배 넘게 늘면 실패")이 틀려서 "딱 두 배여도 실패"로 정정.
  - 사용자가 영어 응답을 지적함. 이후 한국어로만 답함.
- 결과물: PR #8 머지(master `489767a`). 커밋 `a5a0c9e`(재현 테스트), `37663e0`(수정). 변경 파일: `MovedSeriesRelink.kt`, `TakenOverSeriesCleanup.kt`, `TakenOverSeriesCleanupTest.kt`(+3 테스트), `FORK_NOTES.md`. 전체 테스트(UTF-8) 통과, ktlint 통과. NAS 배포 후 확인은 아직.
